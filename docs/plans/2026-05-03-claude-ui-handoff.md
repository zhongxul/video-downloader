## 页面职责

### 1. 下载

定位：

- 默认首页
- 负责粘贴链接并开始解析
- 展示轻量摘要信息，不承担复杂列表职责

当前设计重点：

- 顶部是工作台式标题区
- 中部是链接输入卡
- 输入卡下方只有一个主动作：`开始解析`
- 下方展示摘要状态，如今日完成、排队中、最近一次解析、队列摘要

注意：

- 这里不能再出现“下载当前 / 下载全部”这类确认页动作
- 首页只负责开始解析，不直接承担资源选择

### 2. 资源确认页

定位：

- 解析完成后的唯一确认界面
- 用户在这里确认资源内容，再执行下载

当前设计重点：

- 顶部返回与轻量标签
- 中部大预览区
- 缩略图切换区
- 标题与资源信息
- 底部两个动作：`下载当前`、`下载全部`

已确认样式要求：

- 底部两个下载按钮都为白底样式
- 该页要突出“确认后再下载”

### 3. 资源库

定位：

- 统一资源中心
- 统一承接进行中、已完成、解析记录

当前设计重点：

- 顶部说明区
- 分段切换器
- 进行中任务摘要卡
- 已完成内容预览区
- 解析记录区

说明：

- Claude 在实现时不需要再恢复旧的多入口历史结构
- 资源库是唯一历史中心

### 4. 详情页

定位：

- 单条任务 / 单条资源的诊断页

当前设计重点：

- 顶部返回和更多
- 状态标签
- 预览区
- 标题、副说明
- 任务信息卡
- 操作建议卡
- 底部操作区

底部动作当前稿面含义：

- `删除记录`
- `打开内容`

说明：

- 详情页偏“诊断型”，不是通用列表页
- 信息布局要优先考虑任务状态、保存路径、错误原因、可执行动作

### 5. 我的

定位：

- 低频设置与帮助页

当前设计重点：

- 顶部只保留小标签，不要再显示大段说明标题
- 主卡片展示“本机下载中心”
- 两张摘要卡：命名规则、网络策略
- 常用设置卡
- 帮助与诊断卡

已确认调整：

- 原先顶部“管理下载偏好、命名方式和网络策略”这段文案已删除

## 当前设计约束

Claude 做 UI 时需要遵守以下边界：

- 只基于当前 5 个页面实现，不额外扩页
- 不重启旧版历史页结构
- 不自行新增复杂业务流
- 不把数据库实体直接暴露到 Compose 页面
- 不在 UI 层创造新的领域模型替代现有 parser/download 结构

## 现有 UI 代码处理原则

这一轮必须明确：

- 现有 UI 代码要管，但不要立刻大改
- 现有 UI 代码先保留，作为旧逻辑参考和功能兜底
- 新设计不要继续直接堆在旧页面文件上

Claude 在实现时应遵守以下原则：

- 优先新建页面层代码，而不是直接重写旧页面
- 新 UI 尽量使用新的页面目录、新的 `Screen`、新的 `ViewModel` 骨架
- 不要一开始就删除旧的 `Home / History / Detail / Settings` 相关页面
- 旧 UI 当前属于过渡资产，不是后续继续演进的主战场
- 等新 UI 完成且 Codex 把真实功能接入稳定后，再决定清理旧页面

这样处理的原因是：

- 现有功能目前仍然挂在旧 UI 上
- 如果一开始就硬改旧页面，容易把旧逻辑和新设计缠死
- 新旧并行一段时间，更利于联调、对照和回退
