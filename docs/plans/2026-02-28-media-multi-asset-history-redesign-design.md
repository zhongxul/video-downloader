# 多媒体解析与历史页重构设计文档（方案三）

> 日期：2026-02-28  
> 状态：已评审通过（用户确认）

## 1. 背景与目标

当前应用在以下方面存在明显限制：

1. 抖音仅偏向单视频链路，缺少图集/动图下载能力。
2. X 推文多媒体（多视频、图文混合）仅解析首个视频，无法完整保序展示。
3. 解析结果展示为“格式列表”，缺少统一的媒体预览页与内置浏览体验。
4. 历史页交互负担重，按钮分散，批量任务与失败重试效率低。

本次重构目标：

1. 统一输出“帖子级多媒体结果”，支持抖音与 X 的多媒体保序解析。
2. 支持媒体级下载（单个下载）与批量下载（下载全部）。
3. 引入“批量主任务 + 子任务”任务模型，支持部分成功状态。
4. 重做历史页信息架构与交互流程，提升高频操作效率。

## 2. 关键决策（用户确认）

1. 采用方案三（重构型方案）。
2. 数据库采用 destructive migration（允许清库）。
3. 仅要求保留 X Cookie（使用 SharedPreferences，不随数据库清空）。
4. 历史页采用三栏分区：下载 / 已完成 / 解析记录。
5. 历史页默认标签：下载。
6. 已完成并入历史页，不保留独立已完成页入口。
7. 下载下分二级：下载中 / 下载失败。
8. 批量主任务默认折叠，会话内记忆展开状态，重启后恢复折叠。
9. 交互规则：
   - 普通任务：点击直接进详情。
   - 批量主任务：点击仅展开/折叠。
   - 批量子项：点击进入对应详情。
   - 去掉卡片“详情按钮”等多余操作按钮。
10. 管理模式入口：长按进入 + 顶部按钮进入。
11. 下载页“全选”覆盖主任务与全部子项（含折叠项）。
12. 同一批量任务可同时出现在下载中与下载失败两个分段：
    - 下载中仅展示进行中的子项。
    - 下载失败展示失败子项（可复制主任务视图）。
13. 下载失败分段支持“一键重试全部失败子项”。
14. 信息密度策略：
    - 下载：紧凑列表。
    - 已完成：大卡片。
    - 解析记录：中密度卡片。
15. 文件命名：
    - 图片：优先使用下载链接文件名，缺失时兜底 `标题_序号.扩展名`。
    - 视频：沿用现有默认命名策略。
16. 动图下载策略：优先原格式（GIF/WebP），失败回退 MP4。

## 3. 范围定义

### 3.1 本次在范围内

1. 解析模型重构为帖子级多媒体结构。
2. Douyin 图集/动图解析能力接入。
3. X 多媒体保序解析与媒体级推荐源选择。
4. 新增解析结果页（单项直显、多项横滑、内置预览）。
5. 任务模型升级为 TaskGroup + TaskItem。
6. 历史页全面重构（含下载二级分段）。
7. 批量失败子项一键重试。

### 3.2 本次不在范围内

1. 云端同步与跨端历史同步。
2. iOS 客户端改造。
3. 非必要的视觉主题系统重做。
4. SAMPLE-AES 等更复杂 DRM 解密方案。

## 4. 数据与领域模型设计

### 4.1 解析结果模型

新增领域模型：

1. `ParsedPost`
   - `platform`
   - `sourceUrl`
   - `title`
   - `coverUrl`
   - `mediaItems: List<ParsedMediaItem>`（严格保序）
2. `ParsedMediaItem`
   - `mediaId`
   - `mediaType`（image/video/gif/livePhoto）
   - `displayOrder`
   - `previewUrl`
   - `candidates: List<DownloadCandidate>`
3. `DownloadCandidate`
   - `candidateId`
   - `downloadUrl`
   - `ext`
   - `resolution/bitrate/size`
   - `isRecommended`

### 4.2 下载任务模型

新增任务层级：

1. `TaskGroup`（批量主任务）
2. `TaskItem`（媒体子任务）

状态设计：

1. 子任务状态：`QUEUED`、`DOWNLOADING`、`SUCCESS`、`FAILED`、`CANCELED`
2. 主任务聚合状态：`DOWNLOADING`、`FAILED`、`PARTIAL_SUCCESS`、`SUCCESS`

聚合规则：

1. 有进行中子任务则主任务为 `DOWNLOADING`。
2. 全部结束且全失败/取消为 `FAILED`。
3. 成功与失败并存为 `PARTIAL_SUCCESS`。
4. 全部成功为 `SUCCESS`。

## 5. 数据库设计与迁移

### 5.1 Room 升级

数据库版本升级到 `v4`，并保持 `fallbackToDestructiveMigration`。

新增表：

1. `task_groups`
2. `task_items`（替代当前 `download_tasks` 语义）

保留并扩展：

1. `parse_records`（可增加媒体计数与平台字段，支持结果快照）

### 5.2 X Cookie 保留机制

X Cookie 存储在 `SharedPreferences(video_downloader_settings)`，不在 Room 中，清库不影响 Cookie。

## 6. 解析链路设计

### 6.1 Douyin

1. 单视频：沿用现有视频解析能力。
2. 图集：输出多媒体项（每图一项），顺序与原内容一致。
3. 动图：优先输出原格式下载候选，必要时附加 MP4 回退候选。

### 6.2 X

1. 按推文媒体数组顺序输出媒体项。
2. 每个媒体项独立选择推荐候选：
   - 有推荐则默认推荐候选。
   - 无推荐则默认首个可下载候选。
3. 对多视频/图文混排场景保序展示。

## 7. 下载与重试流程

### 7.1 单个下载

1. 从解析结果页选择单媒体。
2. 创建 `TaskItem`（可不关联 `TaskGroup`）。
3. 入队下载，状态同步与历史展示按子任务处理。

### 7.2 下载全部

1. 创建 `TaskGroup`。
2. 为每个媒体创建 `TaskItem` 并关联 `groupId`。
3. 批量入队并按子任务状态更新主任务聚合状态。

### 7.3 批量失败重试

1. 在下载失败分段提供“重试全部失败子项”。
2. 仅重试失败子项，不重复成功子项。
3. 重试后重新聚合主任务状态。

## 8. 页面与交互设计

### 8.1 解析结果页（新增）

1. 单媒体：直接展示。
2. 多媒体：横向滑动（Pager）浏览。
3. 图片：点击全屏放大查看。
4. 视频：应用内播放器播放。
5. 顶部支持“下载全部”，单卡支持“下载当前”。

### 8.2 历史页（重构）

一级标签：

1. 下载
2. 已完成
3. 解析记录

下载二级分段：

1. 下载中
2. 下载失败

列表行为：

1. 主任务点击展开/折叠。
2. 普通任务点击进详情。
3. 子任务点击进详情。
4. 管理模式支持长按和顶栏按钮进入。
5. 全选覆盖主任务与全部子项。

双分段投影规则：

1. 同一主任务允许同时出现于下载中和下载失败。
2. 下载中只展示进行中子项。
3. 下载失败只展示失败子项。

## 9. 可观测性与错误处理

1. 子任务存储明确错误消息与可选错误码。
2. 主任务展示聚合计数（成功/失败/进行中）。
3. 批量重试输出统一提示与日志。
4. 保持原有下载校验策略，防止网页/错误文本进入已完成。

## 11. 分阶段实施

1. 阶段A：模型与数据库底座。
2. 阶段B：解析链升级（Douyin 图集 + X 多媒体保序）。
3. 阶段C：解析结果页与内置预览。
4. 阶段D：历史页重构（三栏 + 二级分段 + 批量交互）。
5. 阶段E：回归验证与稳定性收敛。

## 12. 验收标准

1. X 多媒体推文可按原文顺序完整解析展示。
2. Douyin 图集可展示并下载图片/动图，动图优先原格式。
3. 支持单个下载与下载全部，且下载全部生成主任务+子任务。
4. 历史页满足新交互规则（点击行为、分段展示、管理模式）。
5. 下载失败分段可一键重试失败子项。
6. 数据库清库后 X Cookie 仍可使用。
