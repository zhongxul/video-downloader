# 安卓本地视频下载 App 技术设计文档（当前实现）

> 文档版本：v1.6.0
> 最后更新：2026-05-07

> 说明：本文描述当前已落地实现；`docs/plans/` 中的 `ParsedPost`、`TaskGroup` 等设计尚未落地。

## 1. 技术栈
- 语言与 UI：Kotlin + Jetpack Compose
- 架构：MVVM + UseCase + Repository
- 存储：Room v3
- 网络：OkHttp
- 下载：Android DownloadManager + 内部 m3u8 分片下载
- 播放：AndroidX Media3 / ExoPlayer（含 HLS 扩展）
- X 解析回退：yt-dlp-android
- 抖音详情解析：App 内 Web 签名请求 + Cookie 可选增强

## 2. 当前核心模型
- 解析结果：`ParsedVideoInfo + List<VideoFormat>`
- 下载任务：单 `DownloadTask`
- 解析记录：`ParseRecord`
- 说明：当前“批量下载”“失败组重试”由 UI 按 `parseRecordId` 做分组展示，不是真正的 `TaskGroup + TaskItem` 结构。

## 3. 模块划分
- `ui/`：Compose 页面、状态展示、交互
- `ui/redesign/`：当前主 UI，包含下载、资源库、资源确认、详情、我的与新导航
- `domain/`：模型与用例（解析、建任务、状态同步、重试）
- `data/`：Room 实体、DAO、Repository
- `parser/`：WebParser + DouyinSignedWebParser + YtDlpParser + Hybrid 聚合
- `download/`：下载网关、预检、结果校验、媒体库扫描
- `di/`：`AppContainer` 手工依赖注入

## 4. 核心流程
### 4.1 解析流程
入口：`DownloadViewModel` / `ParseLinkUseCase`
1. `ParseLinkUseCase` 从输入文案提取 URL。
2. X 链接先经 `XCookieValidator` 预校验。
3. `HybridParserGateway` 先走 Web 解析；当抖音分享页只解析到图片时，走 App 内抖音签名详情解析补充视频资源；失败再走 yt-dlp。
4. Web 解析中优先尝试 kstore hash 页面解码。
5. 解析成功后通过 `ParseResultStore` 将结果传到 `ui/redesign/parse_result/ParseResultScreen`。
6. X/FX 解析结果先经过 `FormatRanking` 过滤与推荐：排除明显非视频项，同一视频多清晰度只保留推荐项或默认首个视频项。
7. 资源确认页按 `VideoFormat` 列表展示真实缩略图；缩略区只做展示和选择，视频通过主展示区播放按钮进入内置播放器。

### 4.2 抖音详情解析
实现：`DouyinSignedWebParserGateway` + `parser/douyin/*`
- `DouyinDetailRequestBuilder` 构造抖音 Web 详情接口请求，并通过 `DouyinABogusSigner` 生成签名参数。
- `DouyinCookieStore` 保存用户手动填写的抖音 Cookie，供详情接口请求使用。
- `DouyinDetailMediaExtractor` 只从 `aweme_detail.images[]` 等结构化字段提取图片、动图/实况图视频资源，避免全 JSON 递归误抓头像、贴纸、配乐封面等无关资源。
- 对 `images[].video.play_addr` 这类资源，优先选择同组第二个视频候选；封面只写入 `VideoFormat.thumbnailUrl` 供 UI 展示。
- `VideoFormat.pairedImageUrl` 仅表示该 mp4 有对应封面图，可用于预览/命名规划；当前下载不再额外生成封面或实况图片。
- 动图/实况图类资源通过 `DynamicPhotoDownloadPlanner` 收敛为单个 `_动态.mp4` 下载项。

### 4.3 kstore hash 链接解析
实现：`WebParserGateway.parseBlueGayHash()`
- 识别规则：URL 含 `kstore.vip/` 且含 `.html#`
- hash 解码规则：`- -> +`、`_ -> /`、`. -> =` 后做 Base64 解码
- 解析 JSON 得到 `title/url`，并生成可下载 `VideoFormat`

### 4.4 X 解析提速策略
实现：`WebParserGateway.parseXFast()`
- `status` 链接：并行发起 `syndication + fx`，先返回者即命中
- `broadcast` 链接：优先 `broadcast`，失败再做轻量 meta 兜底
- FX 镜像：`fxtwitter / vxtwitter / fixupx` 并行探测
- X 请求单独短超时客户端，降低慢链路等待成本
- 对图文混合、多视频链接保留不同媒体项；对同一视频的多 m3u8 清晰度按推荐规则收敛为一个展示/下载项

### 4.5 下载流程
入口：`CreateDownloadTaskUseCase`
1. 解析选项通过可下载性校验
2. 调用 `DownloadGateway.startDownload()` 开始任务
3. 网关层先做同名去重，回传最终文件名
4. 用例层回写任务标题，避免历史重名歧义

### 4.6 m3u8 下载流程
实现：`AndroidDownloadGateway`
1. 解析 playlist（master/media）并抽取分片
2. 若存在 `#EXT-X-KEY`：
   - 解析 `METHOD / URI / IV`
   - 当前仅接受 `METHOD=AES-128`
   - 先下载 key，再按分片逐个解密
3. 分片下载采用有限窗口并发，写入时保持顺序
4. 合并后执行结果有效性校验，不合格则删除并标记失败

### 4.7 通知设置流程
实现：`AppSettingsStore` + `ProfileViewModel`
- 我的页通知开关读写本地设置。
- `AndroidDownloadGateway` 发送下载完成通知前读取设置；关闭时跳过完成通知。
- 该开关只控制下载完成通知，不改变下载任务本身。

## 5. 当前主 UI 实现
- 当前入口：`MainActivity -> RedesignNavHost`
- 顶部栏：一级页标题为下载工作台 / 资源库 / 信息中心；二级页使用返回按钮、来源标题或空标题、可选删除按钮
- 底部导航：下载 / 资源库 / 我的，贴近系统底部区域
- 资源确认页：`ui/redesign/parse_result/*`
- 资源库：`ui/redesign/library/*`
- 详情页：`ui/redesign/detail/*`
- 我的页：`ui/redesign/profile/*`
- 旧 Home / History / Detail / Result 页面已清理；当前主 UI 不再保留旧导航入口。
- 设置页仍复用 `ui/screen/settings/*`，由 `RedesignNavHost` 进入。

### 5.1 资源库聚合
- 进行中与已完成均按 `parseRecordId ?: task.id` 做 UI 分组。
- `下载全部` 会为同一批资源创建多个 `DownloadTask`，并共享同一 `parseRecordId`。
- 已完成集合只纳入成功任务；同组失败任务保留在下载列表/失败详情中。
- 失败详情的“重新下载”只重试当前分组内失败任务，成功后继续归入同一 `parseRecordId` 对应的已完成集合。
- 该聚合不是数据库级 `TaskGroup + TaskItem`，只是当前 UI 汇总规则。

### 5.2 媒体预览边界
- `MediaPreview` 支持图片显示、视频首帧抽取和播放按钮覆盖层。
- 资源确认页主展示区按原比例最大展示，视频点击播放按钮进入 App 内播放器；返回时释放播放状态，避免残留画面。
- 资源确认页缩略区只负责选择，不触发播放。
- 已完成列表只显示封面，合集项叠加合集图标。
- 已完成详情改为纵向媒体流；图片进入 App 内查看器，视频通过播放按钮进入 Media3/ExoPlayer 播放器。

### 5.3 X Cookie 设置
- 我的页通过 `RedesignNavHost` 跳转 `XSettingsScreen`。
- Cookie 由设置模块读写，并通过本地加密偏好存储。

### 5.4 抖音 Cookie 设置
- 我的页通过 `RedesignNavHost` 跳转 `DouyinSettingsScreen`。
- Cookie 由 `DouyinCookieStore` 本地保存，仅用于 App 内抖音详情接口请求。
- 抖音解析不依赖电脑、本地 Docker 或 HTTP sidecar。

### 5.5 通知设置
- 我的页通知开关由 `ProfileViewModel` 绑定 `AppSettingsStore`。
- 下载完成通知不再是固定开启状态，而是受本地设置控制。

## 6. 可观测性
- X 解析新增分支耗时日志：
  - `parseXFast success/fail cost=...`
  - `parseXStatusFast branch=... hit=... cost=...`
  - `parseTwitterFx mirror=... hit=... cost=...`

## 7. 已知限制
- 非 `AES-128` 的加密方式（如 `SAMPLE-AES`）不支持
- 链接 `auth_key` 过期后会下载失败，需使用新链接
- X 平台受 Cookie、地区、节点质量影响较大
- 抖音详情接口受 Cookie、签名参数和平台风控影响，可能出现阶段性失败
- 抖音动图/实况图当前只保存 mp4 动态文件，不承诺写成 vivo/系统相册可识别的原生实况图
- 当前尚未实现帖子级多媒体模型与真正的批量任务模型
- 当前解析记录仍无法完整恢复资源确认页的所有交互状态
